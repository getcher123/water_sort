# Публикация на GitHub Pages

Репозиторий: [getcher123/water_sort](https://github.com/getcher123/water_sort). Опубликованная игра: **[https://getcher123.github.io/water_sort/](https://getcher123.github.io/water_sort/)**.

Первая публикация и браузерное прохождение первого уровня подтверждены 7 ноября 2026 года: [отчёт](../qa/pages-release.md), [успешный запуск Actions](https://github.com/getcher123/water_sort/actions/runs/42397252718). Само наличие workflow не заменяет проверку результата каждого нового релиза.

## Первоначальная настройка

Владелец репозитория выполняет один раз:

1. Открывает **Settings → Pages**.
2. В разделе **Build and deployment → Source** выбирает **GitHub Actions**.
3. Открывает **Actions** и workflow из `.github/workflows/pages.yml`.
4. Запускает **Run workflow** для ветки `main` либо повторно запускает неудавшуюся первую сборку после включения Pages.

Если публикация уже была включена и успешно выполнена, повторять настройку не нужно. Последующие изменения в `main` запускают проверку и деплой автоматически.

Стандартный `GITHUB_TOKEN` workflow не заменяет права владельца для первоначального включения Pages в новом репозитории. Не добавляйте персональный токен в исходники и не рассчитывайте, что параметр `enablement: true` сам устранит ограничение прав. Если организация ограничивает Pages или требует подтверждения окружения, настройку и разрешение выполняет уполномоченный пользователь.

## Что делает workflow

Workflow `.github/workflows/pages.yml`:

1. Получает исходники нужного коммита.
2. Подготавливает Node.js 24, Godot 4.6.3 и соответствующие Web-шаблоны экспорта.
3. Импортирует ресурсы, запускает тесты игры и собирает Web-экспорт.
4. Проверяет загрузчик по готовым файлам `dist`.
5. Передаёт `dist` целиком в артефакт GitHub Pages.
6. Развёртывает проверенный артефакт в окружении `github-pages`.

Pull request запускает проверки, но не заменяет опубликованную игру. Публикация выполняется для `main` при push или ручном запуске workflow на этой ветке.

`dist/`, кеш Godot и скачанный движок не хранятся в Git: они заново создаются в CI. Не требуется вручную копировать сборку в ветку `gh-pages`.

Скрипт `scripts/install-godot-ci.sh` предназначен для GitHub Actions и требует `GITHUB_ENV`. Он загружает официальный движок и matching templates, проверяет SHA-256 полных архивов и устанавливает только Web-шаблоны в изолированный временный каталог. Полный архив шаблонов занимает около 1,3 GB; это загрузка на CI-runner, а не на компьютер игрока. Для локальной установки используйте [RUNNING.md](RUNNING.md).

## Доступы и безопасность

- Сборке достаточно чтения исходников: `contents: read`.
- Заданию публикации нужны `pages: write` и `id-token: write`.
- Целевое окружение — `github-pages`. Его правила согласования нужно соблюдать.
- Игра не требует игровых API-ключей, платных генераций, базы данных или пользовательских секретов.

Репозиторий и опубликованная игра доступны публично. Не добавляйте `.env`, приватные материалы или ключи в исходники, `dist` и артефакты сборки. При отказе в доступе исправляйте настройку с владельцем, а не расширяйте глобальные права организации.

## Как проверить результат

1. Во вкладке **Actions** откройте запуск для нужного коммита: проверка, сборка и `deploy` должны завершиться успешно.
2. Откройте адрес из результата deployment или **Settings → Pages**.
3. Дождитесь загрузки, нажмите **Играть** и проверьте выбор двух колб, допустимое и запрещённое переливание.
4. Проверьте отмену, перезапуск, паузу, победу и переход между уровнями.
5. Повторите короткую проверку на настольном и мобильном браузере с WebGL 2.

Успешный HTTP-ответ или зелёный Actions подтверждают доступность файлов и прохождение автоматических проверок, но не заменяют визуальное прохождение WebGL-игры. Фактический результат и непроверенные пункты фиксируются в `state.md`.

## Если публикация не удалась

| Ситуация | Действие |
|---|---|
| Pages site not found / Pages не включён | Проверьте **Settings → Pages → Source: GitHub Actions**, затем повторите workflow |
| Не хватает `pages` или `id-token` прав | Проверьте разрешения конкретного задания и ограничения репозитория; не публикуйте PAT в коде |
| Ожидается согласование окружения | Владелец или назначенный reviewer подтверждает развёртывание в `github-pages` |
| Ошибка Godot или export templates | Проверьте совпадение версий движка и шаблонов; не заменяйте только один компонент |
| Не прошли тесты | Исправьте причину и повторите проверки; не обходите их для публикации |
| Открывается старая версия | Сверьте коммит успешного deployment и полностью перезагрузите страницу |
| Файлы доступны, но игра не запускается | Проверьте WebGL 2, сообщения загрузчика и наличие всех файлов одной сборки |

Для возврата к предыдущему коду используйте обычный revert-коммит или pull request с исправлением. После обновления `main` workflow соберёт и опубликует соответствующую версию. Удаление истории и принудительная перезапись ветки для этого не нужны.
