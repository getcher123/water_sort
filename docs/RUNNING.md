# Запуск и разработка

## Получить исходный код

```bash
git clone https://github.com/getcher123/water_sort.git
cd water_sort
```

Вместо Git можно скачать репозиторий кнопкой **Code → Download ZIP** и распаковать архив. Далее команды выполняются из папки, содержащей `package.json`.

## Самый простой запуск: редактор Godot

1. Установите стандартную версию [Godot 4.6.3 stable](https://godotengine.org/download/archive/4.6.3-stable/). Вариант .NET не требуется: проект написан на GDScript.
2. В менеджере проектов Godot нажмите **Import / Импортировать** и выберите `godot/project.godot`.
3. Дождитесь импорта ресурсов и нажмите **F5** — запустится главная сцена игры.
4. **F8** останавливает запущенную из редактора игру. **F6** запускает текущую сцену, поэтому применяйте его, когда открыта `godot/scenes/main.tscn`.

Для этого варианта Node.js и шаблоны Web-экспорта не нужны. Если на компьютере уже есть другая версия Godot, можно установить 4.6.3 отдельно. Автоматические сборки закреплены за 4.6.3; переход на другую версию требует повторного тестирования.

## Что нужно для Web-сборки

| Компонент | Требование |
|---|---|
| Godot | 4.6.3 stable, стандартная версия |
| Export templates | Точно соответствуют движку: `4.6.3.stable`, включая Web |
| Node.js | 22 или новее; CI использует 24 |
| npm | Поставляется вместе с Node.js; сторонних npm-зависимостей нет |

В Godot откройте **Editor → Manage Export Templates** и установите шаблоны для текущей версии. Настройка экспорта **Web** уже записана в `godot/export_presets.cfg`.

Для публикации используйте `npm run build`: после экспорта он создаёт транспортные файлы движка и манифест. Одиночный экспорт из меню редактора не выполняет эту дополнительную подготовку.

Проверьте доступность инструментов:

```bash
godot --version
node --version
npm --version
```

Скрипты ищут Godot по переменной окружения **`GODOT_BIN`**, а при её отсутствии вызывают команду **`godot`** из `PATH`. Указание `GODOT_BIN` не устанавливает движок или экспортные шаблоны.

### Windows: выбрать установленный Godot без изменения PATH

Откройте PowerShell в корне репозитория и выполните блок целиком. Диалог позволяет выбрать существующий файл Godot; при наличии двух файлов предпочтителен вариант с суффиксом `_console.exe` — он выводит диагностику в терминал.

```powershell
Add-Type -AssemblyName System.Windows.Forms
$gameGodotPicker = New-Object System.Windows.Forms.OpenFileDialog
$gameGodotPicker.Title = 'Выберите Godot 4.6.3'
$gameGodotPicker.Filter = 'Исполняемый файл Godot (*.exe)|*.exe'
$gameGodotPicker.CheckFileExists = $true
if ($gameGodotPicker.ShowDialog() -ne [System.Windows.Forms.DialogResult]::OK) {
    throw 'Godot не выбран. Сборка не запущена.'
}
$env:GODOT_BIN = $gameGodotPicker.FileName
& $env:GODOT_BIN --version
npm.cmd run build
npm.cmd run test:loader
npm.cmd run serve
```

`GODOT_BIN` действует в текущем терминале. `npm.cmd` позволяет запускать npm без изменения системной политики выполнения PowerShell. Экспортные шаблоны Godot необходимо установить заранее через редактор.

## Собрать и открыть в браузере

Из корня репозитория:

```bash
npm run build
npm run test:loader
npm run serve
```

Сборка запускает импорт ресурсов, проверки игры и Web-экспорт. Готовая папка **`dist/`** содержит HTML-оболочку, пакет игры, загрузчик Godot и файлы его WebAssembly-runtime.

Откройте **[http://127.0.0.1:4173/](http://127.0.0.1:4173/)**. Сервер слушает только loopback-интерфейс этого компьютера и отдаёт `dist`. Остановка — `Ctrl+C`. Не запускайте второй экземпляр на том же порту.

Не открывайте HTML через `file://`: браузеру нужен HTTP/HTTPS для загрузки ресурсов. При переносе сборки копируйте **весь `dist`**, а не один `index.html`. Для проверки с телефона используйте опубликованный HTTPS-адрес GitHub Pages: этот локальный сервер специально не открыт в сеть.

Первичная загрузка движка занимает около 10 MB при поддержке распаковки gzip в браузере. Резервный путь загружает около 38 MB исходного WebAssembly. Поэтому задержка первого открытия сама по себе не означает зависание игры.

## Запустить проверки отдельно

```bash
npm test
```

Команда сначала импортирует ресурсы, затем запускает две GDScript-suite: независимую модель и настоящий контроллер сцены в headless-режиме. Тест контроллера использует хранилище прогресса этого проекта; не запускайте его одновременно с открытой игровой сессией, прогресс которой нужно сохранить.

После сборки:

```bash
npm run test:loader
```

Это тесты загрузчика в Node.js с подставными DOM и Engine, но настоящими файлами экспорта. Они проверяют целостность runtime, резервные пути и ошибки загрузки, а не отрисовку WebGL.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Команда `godot` не найдена | Настройте `PATH` или выберите существующий исполняемый файл через `GODOT_BIN` |
| Не найдены export templates | Установите шаблоны точно той же версии, что и движок |
| Ошибка импорта шрифта или ресурса | Дайте редактору завершить импорт; используйте `npm test` или `npm run build`, которые выполняют импорт перед тестами |
| Папка `dist` отсутствует | Сначала выполните `npm run build` и устраните ошибки сборки |
| Порт 4173 занят | Остановите ранее запущенный сервер через его терминал; не завершайте неизвестные процессы |
| WebGL 2 недоступен | Откройте страницу в обычном современном браузере с доступной графикой; встроенный WebView или ограниченное облачное окружение могут не поддерживать нужный режим |
| Ошибка загрузки движка | Проверьте сеть и наличие всех файлов `dist`; не смешивайте файлы разных сборок |
| Открывается пустая страница из файла | Используйте `npm run serve` и HTTP-адрес вместо двойного щелчка по HTML |
| После обновления видна старая версия | Выполните полную перезагрузку страницы; проверьте, что развёрнут нужный коммит |
| Прогресс не сохраняется | Проверьте доступность хранилища браузера; приватный режим или очистка данных могут его сбрасывать |

В предыдущем облачном браузерном окружении WebGL 2 был недоступен. Успешные автоматические тесты не заменяют ручную проверку изображения и управления в браузере с WebGL 2.
